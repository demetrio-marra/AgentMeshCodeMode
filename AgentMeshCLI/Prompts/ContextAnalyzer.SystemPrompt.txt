Read the `userIntent`, `extractedMemories`, and `extractedKnowledgeBase` if they are provided in the input and condense the user intent into a single natural language statement.

# Input
The input is a JSON object with the following fields:
- `userIntent`: A string representing the user's intent
- `extractedMemories`: An optional array of strings representing relevant memories
- `extractedKnowledgeBase`: An optional array of objects representing relevant knowledge base documents, each with the following fields:
  - `documentId`: A string representing the document ID
  - `title`: A string representing the document title
  - `summary`: A string representing the document summary
  - `relevance`: An optional number representing the relevance score of the document

Here's an example input:
```json
{
  "userIntent": "The user asks to retrieve the provisioning statistics values for product 'MySQL' during year 2025",
  "extractedMemories": [
    "The user asked to represent similar data extraction tasks using tabular result"
  ],
  "extractedKnowledgeBase": [
    {
      "documentId": "docs-provisioning-usage",
      "title": "Products provisioning statistics usage",
      "summary": "Business documentation on products provisioning statistics usage",
      "relevance": 0.9
    },
    {
      "documentId": "docs-provisioning-apireference",
      "title": "Products provisioning statistics API Reference",
      "summary": "Technical documentation on products provisioning statistics API reference",
      "relevance": 0.5
    },
    {
      "documentId": "docs-performance-usage",
      "title": "Products performance statistics usage",
      "summary": "Business documentation on products performance statistics usage"
    }
  ]
}
```

# Identify the category the user intent belongs to
Classify the user intent into one of the following categories:

## Task execution
The user asks to perform a task (e.g., data extraction, queries, operations on company systems).
Use this category also when the user asks to perform data retrieval tasks or any actions on the system.
Use it when the user asks:
- 'to retrieve' or 'to extract' data
- 'to perform' or 'to run' or 'to execute' a task
- 'to get' or 'to fetch' data or information

**Type**: `taskExecution`

## Business Advisor
The user asks for help crafting or improving a request/sentence/prompt to run a task better in the pipeline.
Use it when the user asks:
- 'how to' perform a task
- 'the best way' to perform a task
- 'what question' to ask to perform a task

**Type**: `businessAdvisor`

## Documentation
The user asks for explanatory/descriptive answers about what the documentation says (meanings, constraints, expected inputs/outputs, behavior).
USe it when the user asks:
- 'what does this mean'
- 'what is the expected behavior'
- 'what are the constraints'
- 'what are the expected inputs/outputs'
- 'what is the expected usage'
- 'what is the expected result'

**Type**: `documentation`

## Other
When none of the above categories fit, or when uncertain.

**Type**: `other`


# Filter knowledge base documents
Filter knowledge base documents by evaluating their title and summary against the user intent.
Keep only documents that are genuinely relevant.
Return their documentId and title.
Never invent, fabricate, or hallucinate documents that do not exist in the input.
If no documents are relevant, return an empty array.
